# Require Node 26 in package.json

- **Date:** 2026-11-14
- **Branch:** task/145-engines-node-26
- **Issue:** [#145](https://github.com/hawkins48b/cw-zro/issues/145)
- **Status:** Delivered

## Summary

Since #144 the toolchain is on Node 26, and CI runs only Node 26. However, `package.json` did not say which Node version it needs. As a result, `npm ci` still accepted Node 22.22.2 or later and 24.15 or later, which are no longer tested.

**Delivered:** `package.json` now requires Node 26 or later. With `engine-strict=true` in `.npmrc`, `npm ci` on an older Node stops with `EBADENGINE`. Developers need Node 26. Nothing changes for users or on the server.

## Technical changes

- [`package.json`](../package.json): `"engines": { "node": ">=26" }`.
- [`package-lock.json`](../package-lock.json): the same `engines` field was added by hand to the root entry. The security reviewer confirmed the result is byte-identical to the lockfile npm produces with the field. Running `npm install --package-lock-only` also dropped some `"dev": true` flags on optional platform packages. That change is unrelated, so it was left out.
- [`README.md`](../README.md) and [`docs/development.md`](development.md): the requirements text says `package.json` requires Node 26. The common-problems row for `EBADENGINE` now gives "Node older than 26" as the cause and `nvm install` as the fix.
- The range is `>=26`. `^26` was also considered, but CI already pins the major version through `.nvmrc`.

## Known limitations / follow-ups

- Not yet confirmed: if Dependabot's npm updater runs on a Node older than 26, its update runs will fail with `EBADENGINE` and no Dependabot PRs will appear. After a release brings `dependabot.yml` and `engines` to `main` (#78), check the Dependabot job log after the first weekly run. If it does fail, the fix is to move `engine-strict` out of `.npmrc` and into CI.
