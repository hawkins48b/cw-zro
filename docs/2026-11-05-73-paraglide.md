# Paraglide 3

- **Date:** 2026-11-05
- **Branch:** task/73-paraglide
- **Issue:** [#73](https://github.com/hawkins48b/cw-zro/issues/73)
- **Status:** Delivered on `develop`, not in production yet

## Summary

The goal was to move `@inlang/paraglide-js` to version 3, with all three languages and locale URLs still working.

**Delivered:** Paraglide goes from 2.29.3 to 3.1.0 and no application code changed. Builds no longer run remote code, and a new test fails if the message catalog comes out empty.

### Effect on users

None. Text, charts and PDFs match `develop` in every comparison run, and bundle sizes are almost unchanged: web JS -47 bytes, mobile JS +1,477 bytes.

## Technical changes

[`vite.config.js`](../vite.config.js), the hooks and the 17 runtime and server imports (one is a `vi.mock` in a test) are untouched.

Breaking changes in version 3:

- **Applied here:** virtual modules are now the Vite default, so `messages.js` needs the Vite plugin. Build and Vitest both use it.
- **Not used here:** `additionalFiles`, `experimentalMiddlewareLocaleSplitting` and `trackMessageCall` were removed.

Other changes:

- **`pathPattern`** in [`settings.json`](../project.inlang/settings.json) now uses `{locale}`.
- **Generated output:** `src/lib/paraglide` is generated and git-ignored. `/project.inlang/cache/` was added to [`.gitignore`](../.gitignore), because the v3 build no longer writes its own ignore file there.

## Remote code removed from the build

[`settings.json`](../project.inlang/settings.json) loaded four modules from jsDelivr at `@latest`, so unpinned remote code ran during builds.

- **Now:** one local module, `./node_modules/@inlang/plugin-message-format/dist/index.js`. It is `@inlang/plugin-message-format` 4.6.0, a devDependency pinned by the lockfile.
- **Removed:** the three lint modules. The SDK fetched and ran them, then discarded them.
- **Result:** a clean build with the network blocked exits 0 with no network attempts.
- **Recheck on SDK upgrades:** the SDK calls local module paths "backwards compatibility".

## New test

Paraglide only warns when it cannot load messages, and the build then succeeds with an empty catalog. [`messages.test.js`](../src/test/messages.test.js) fails in that case, which was confirmed by breaking `pathPattern`: all 353 keys were reported missing. CI runs tests before the build.

## Checks

**423 passed, 1 todo.** `npm ci` on npm 10 leaves the lockfile unchanged, and `build` and `build:mobile` pass. `npm audit` is unchanged at 11 total, 4 with `--omit=dev`. The test run, `npm audit` and the key count per language were rerun for this document; the builds and browser checks were not.

- **Messages:** 353 keys in each language, and every key used in `src` exists. All 1,059 key and locale outputs match the JSON and match v2.
- **Browser smoke against `origin/develop`:** same results on `vite preview`, a static host and the mobile build, with no differences in text, charts or PDF hashes. 60 of 60 screenshots are pixel-identical, and 42 route and locale pages match.
- **Electron and Capacitor:** the runtimes cannot start here. v2 and v3 gave 0 differences across 390 logic cases of origin, path and cookie state.

## Deployment notes

Nothing to run or configure. Builds need devDependencies, because the message plugin is one; the plain `npm ci` in CI installs them.

## Security review

**PASS**, no findings. The lockfile is clean, no remote code runs at build time, and `src/lib/paraglide/server.js` stays out of the client bundle.

## Known limitations / follow-ups

- **Not verified:** real Electron and Capacitor runtimes, `electron-builder` packaging, and message hot reload in dev.
- **Existing issue, same on `develop`:** the language choice does not persist. The `url` strategy matches first, and a path with no prefix resolves to `en` and overwrites the cookie, so native apps should cold-start in English.
- **Existing issue, same on `develop`:** `<html lang>` stays `en` on `/fr` and `/de` on static hosts and mobile.
