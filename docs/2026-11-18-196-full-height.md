# 2026-11-18: Phone layout full height on Firefox for Android

Issue: [#196](https://github.com/hawkins48b/cw-zro/issues/196). Branch `task/196-full-height`.

## Problem

The owner reported that, on a phone in Firefox for Android, the app did not fill the screen. There was an empty strip below the bottom tab bar.

## Change

One file: [`src/routes/+layout.svelte`](../src/routes/+layout.svelte), the app shell.

| Before | After |
|--------|-------|
| Shell sized with `h-dvh` (100 dynamic viewport height) | Shell pinned to the screen with `fixed inset-0` |
| Bottom safe-area padding on the shell, under the tab bar, in the page background colour | Phone tab bar shown: the inset goes inside the tab bar (`pb-[calc(0.25rem+var(--safe-area-bottom))]`), in the bar's colour. Tablet, desktop, bare pages and editors: on the shell, as before |

The top safe-area padding is unchanged. `main` was already the only scroll area, so nothing depended on the document scrolling.

## Cause

Not confirmed on a device. The two likely causes, both removed by the change:

- Firefox for Android can resolve `100dvh` to a height smaller than the visible area (dynamic toolbar). A fixed box with `inset: 0` follows the visible area without viewport units.
- A bottom safe-area inset reported while Firefox's own toolbar already sits above the system bar. It now shows as part of the tab bar, not as an empty strip.

## Checks

- `npm run test:run`: 70 files, 4999 passed.
- `npm run build`: passes, the new classes are in the CSS.
- Security review: PASS (classes are fixed literals, no new inline style, no CSP or data change).
- Not run in a browser, on a phone, in Electron or in the Capacitor apps.

## To test

On a phone, open the dev site or a local build:

1. Firefox for Android, portrait: the tab bar touches the bottom of the visible area, no gap. Scroll a long page: the bar stays put.
2. Chrome for Android and iOS Safari: same, and on iOS the tab bar clears the home indicator.
3. Capacitor app (iOS with a home indicator): tab bar background reaches the screen edge, icons above the indicator.
4. Welcome screen and guided setup (bare pages), and a profile editor (no tab bar): content still clears the bottom inset.
5. Tablet and desktop: unchanged.

## Follow-up: the tab bar was too tall

After the release (37c126c) the owner sent a Firefox for Android screenshot (3-button navigation bar). The gap was gone, but the tab bar had an empty band at the bottom as tall as the navigation bar. The page ends above that bar, yet Firefox reports its height as `env(safe-area-inset-bottom)`. This confirms the second cause above.

[`src/app.css`](../src/app.css) now sets `--safe-area-bottom` to `0px` inside `@supports (-moz-appearance: none)`, which only Gecko matches. This also applies to the toast and the dialogs, which use the same variable. Firefox on iOS is WebKit and keeps the inset. Desktop Firefox has no inset anyway.

Security review: PASS (static rule in the bundled stylesheet, no CSP change).

Open: if a future Firefox for Android draws the page behind the system bar, this rule would let the tab bar sit under it. Not checked with gesture navigation, or on Chrome, iOS Safari or the Capacitor apps.
