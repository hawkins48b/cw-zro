# Node 26 LTS toolchain

- **Date:** 2026-11-14
- **Branch:** task/144-node-26
- **Issue:** [#144](https://github.com/hawkins48b/cw-zro/issues/144)
- **Status:** Delivered with known issues (native mobile builds were not run)

## Summary

The project was pinned to Node 22, which is now in maintenance. Node 26 has been the active LTS since October 2026. The task was to move the toolchain to Node 26.

**Delivered:** `.nvmrc` says `26`, and the docs name Node 26. No dependency and no lockfile entry changed: every dependency already accepts Node 26, and `npm ci` on Node 26 leaves `package-lock.json` unchanged. Nothing changes for users or on the server. Developers need Node 26 and a fresh `npm ci`.

## Technical changes

- [`.nvmrc`](../.nvmrc): `22` → `26`. CI reads it through `node-version-file`, so the workflows did not change and CI installs the latest 26.x.
- [`README.md`](../README.md), [`CLAUDE.md`](../CLAUDE.md) and [`docs/development.md`](development.md) name Node 26 and npm 11.20.0. `development.md` also notes that the dependencies would still run on Node 22.22.2 or later (the `jsdom` 31 floor), that Vitest 5 does not accept Node 25, and explains the npm 11 `allowScripts` warning (below).

### npm 11 install scripts

npm 11 warns during `npm ci` that `electron-winstaller@5.4.0` has an install script "not yet covered by allowScripts". It only warns: the script still runs and copies the bundled 7-Zip binary for the host CPU architecture into its `vendor/` folder. `fsevents` is the only other package with an install script, and it installs on macOS only.

### cw-lab dev container

On the cw-lab root repo, not this branch: `container/claude/Dockerfile` now copies `node` and `npm` from `docker.io/node:26-slim`. The container is shared with chocolatewarfare, so its Node users were checked on 26.13.1 too: its editor bundle `npm run check` (bundle up to date) and the six Node-backed PHPUnit specs (`DeployWorkflowsSpec`, `CwActionsSpec`, `MarkdownEditorSmokeSpec`, `PrimaryPaletteSpec`, `MarkdownDialectRoundTripSpec`, `MarkdownPreviewParitySpec`) pass. chocolatewarfare's own CI still pins Node 22.11.0; that was not changed.
