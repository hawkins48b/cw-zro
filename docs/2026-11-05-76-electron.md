# Electron 45 and a working desktop package

- **Date:** 2026-11-05
- **Branch:** task/76-electron
- **Issue:** [#76](https://github.com/hawkins48b/cw-zro/issues/76)
- **Status:** Delivered on `develop`, not in production yet

## Summary

The goal was to move Electron to version 45, review the app against each major's breaking changes, and confirm that the desktop app starts, handles deep links and exports PDFs.

**Delivered:**

| Package | From | To |
|---------|------|----|
| `electron` | 40.10.6 | 45.2.3 (Chromium 156) |
| `electron-builder` | 26.18.1 | 26.18.1 |
| `electron-serve` | 3.0.1, devDependency | 3.0.1, dependency |

The work also fixed a problem older than this upgrade: **the packaged app could not start.** `electron-serve` was a devDependency, so a packaged build crashed with `ERR_MODULE_NOT_FOUND` even though the build itself reported success.

### Effect on users

- The Linux package now starts. It was run on Linux only: **Windows and macOS were not run**, and no Windows installer or dmg was built.
- External links open in the system browser, and the app window can no longer leave the app.
- The app has its own icon, rendered from the ZRO logo.
- Save dialogs now open in Downloads by default.
- The minimum macOS is now 13, and 32-bit Windows and armv7l are no longer supported.

## How to use

- `npm run electron:dev` builds the app and opens it in Electron. After a fresh install, the first `electron .` downloads the Electron binary.
- `npm run electron:build` builds the desktop package into `dist-electron/`. On Linux this is `ZRO-2.0.0.AppImage`, 126 MB.

## Technical changes

- **Packaging:** [`electron-builder.json`](../electron-builder.json) excludes all of `node_modules` except `electron-serve`, because Vite bundles everything else. `app.asar` went from 253 MB and 114 packages to 1.7 MB.
- **Navigation guard:** [`electron/main.js`](../electron/main.js) applies the rules below, using URL checks from [`electron/navigation.js`](../electron/navigation.js).
- **Preload:** `electron/preload.js` is now [`electron/preload.cjs`](../electron/preload.cjs), with `sandbox: true` set explicitly. It exposes nothing to the page. It is `.cjs` because no single `.js` form works in both sandbox modes.
- **Icons:** [`resources/icon.ico`](../resources/icon.ico) and [`resources/icon.icns`](../resources/icon.icns) are rendered from [`static/logo.svg`](../static/logo.svg), replacing the `build/favicon.png` setting. `buildResources` is `resources` because the default, `build`, is SvelteKit's output.
- **Linux desktop link:** `desktopName` in [`package.json`](../package.json) and `syncDesktopName` link the window to its icon.
- **Updates:** `publish` is `null` because there is no updater.
- **Tests:** 34 new tests in [`src/test/electronNavigation.test.js`](../src/test/electronNavigation.test.js).

## Navigation rules

| Request | Result |
|---------|--------|
| A page asks for a new window | Always denied |
| New window request for an `https:` URL | Denied, and the URL opens in the system browser through `shell.openExternal` |
| Main window navigates within `app://-` | Allowed |
| Main window navigates anywhere else | Blocked |

The rules compare protocol and host, not origin, because `new URL('app://-/').origin` is the string `'null'` in the main process.

An external link without `target="_blank"` is blocked rather than opened in the browser. The app has no such links today, so new external links must use `target="_blank"`.

## Breaking changes reviewed

| Major | Change | Effect here |
|-------|--------|-------------|
| 41 | In-window PDF change | Does not apply: PDFs are downloaded |
| 42 | `postinstall` no longer downloads the binary | The first `electron .` fetches it |
| 43 | Save dialogs default to Downloads | Applies to the app's save dialogs |
| 44 | macOS 13 is the minimum; no 32-bit Windows or armv7l | Fewer supported platforms |
| 45 | Sandboxed preloads lose `Buffer` and Node shims | The preload uses neither |
| 45 | ASAR file descriptor change | Reviewed |
| 45 | `window.open` child change | Does not apply: all new windows are denied |

## Security review

**PASS**, no blocking findings. The remaining hardening items are listed below and are left open.

## Known limitations / follow-ups

**Not verified:**

- Windows and macOS were not run, and no Windows installer or dmg was built here. The Windows build stops at wine.
- A real browser opening through `xdg-open`.
- Wayland.
- The look of the exported PDFs.
- Hosts with user namespaces disabled.

**Left open:**

- **Language:** it resets to English on every launch. This is existing behaviour, and fixing it needs a change to the locale strategy.
- **Linux sandbox:** the AppImage does not always run with Chromium's OS sandbox. electron-builder's default desktop entry turns it off, and the AppImage launcher also does so on hosts without user namespaces.
- **Electron fuses:** these are at their defaults, so the optional hardening of the packaged binary has not been applied.
- **Missing protections:** there are no permission handlers and no Content-Security-Policy.
- **Distribution:** there is no auto-update, code signing or build workflow.
- **Icon generator:** it was scratch-only, so regenerating the icons needs a new script.
- **`npm audit --json`:** it currently fails with a 400 on the retired endpoint with npm 10.9.9. Plain `npm audit` works.
- **Builder warnings:** `author` is missing and the Linux category is the default.
