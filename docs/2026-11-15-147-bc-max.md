# Upper limit for the BC

- **Date:** 2026-11-15
- **Branch:** task/147-bc-max
- **Issue:** [#147](https://github.com/hawkins48b/cw-zro/issues/147)
- **Status:** Delivered, not in production yet

## Summary

The BC had only a lower limit (`MIN_BC = 0.01`, #119). A BC of 50 or 1e300 was accepted by the profile form and every calculation path, and gave a normal-looking result. No real bullet comes near such values, and the hang probes of #89 only covered BC up to 2.

**Delivered:** a BC from 0.01 to 2, both included, G1 or G7 (owner decision of 2026-11-15). Above 2, the profile form shows an error under the BC box, and the calculators and both dope cards give no result. A BC of exactly 2 still works. The bundled ammunition BCs are 0.13 to 1.05, so none is affected. No calculated result changed and no recorded baseline changed.

**Release note:** a BC above 2 is refused. Profiles saved earlier with such a BC give no result in the calculators and dope cards until they are edited; the profile form shows the range error on the BC.

## Message

The BC has no unit, so the form uses a new message without one:

| Language | Message |
|----------|---------|
| en | Enter a number from {min} to {max} |
| fr | Saisissez un nombre de {min} à {max} |
| de | Geben Sie eine Zahl von {min} bis {max} ein |

For the BC this reads "Enter a number from 0.01 to 2". It replaces the former "Enter a number of at least 0.01". No other screen changed.

## Technical changes

- [`src/lib/utils/inputLimits.js`](../src/lib/utils/inputLimits.js): new `MAX_BC = 2` next to `MIN_BC`. `isUsableBc` checks `bc <= MAX_BC` too, so all five engine paths (shot point, full trajectory, MPBR, both dope cards) refuse a BC above 2 before the engine is called.
- [`src/lib/utils/profileValidation.js`](../src/lib/utils/profileValidation.js): the BC limit is `{ kind: 'range', min: 0.01, max: 2 }` without a unit, and `isWithinLimits` checks both ends. The `'min'` limit kind, used only by the BC, is removed.
- [`src/lib/components/ProfileForm.svelte`](../src/lib/components/ProfileForm.svelte): a `'range'` limit without a unit uses `validation_range_no_unit`; the `'min'` case is removed.
- [`src/lib/utils/trajectoryValidation.js`](../src/lib/utils/trajectoryValidation.js): the upper bound of the BC search reads `MAX_BC` instead of a hard-coded `2.0`. Same value, no behaviour change.
- `messages/en.json`, `messages/fr.json`, `messages/de.json`: new `validation_range_no_unit`; the unused `validation_min` is removed.
- [`docs/ballistics-model.md`](ballistics-model.md): the limits table gives the BC as 0.01 to 2, the guards table names the new range on all five paths, and the Trajectory Validation row says that both ends of its BC search are excluded.
- [`docs/testing.md`](testing.md): new test counts.
