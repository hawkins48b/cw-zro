## Desktop hardening (#104)

| Piece | File | What it does |
|-------|------|--------------|
| Permissions | [`electron/permissions.js`](../electron/permissions.js) | `denyAllPermissions(session)` sets the permission request, permission check and device permission handlers of the default session. All refuse |
| Menu | [`electron/menu.js`](../electron/menu.js) | `buildMenuTemplate({ isMac, isPackaged })`: the macOS app menu (macOS only), File, Edit, a custom View (reset zoom, zoom in, zoom out, full screen) and Window. Reload and Toggle Developer Tools are added to View only when `isPackaged` is false. Electron's `viewMenu` role is not used because it includes both |
| Wiring | [`electron/main.js`](../electron/main.js) | In `app.whenReady()`: denies permissions on `session.defaultSession`, sets the menu, then creates the window |
| Fuses | `electronFuses` in [`electron-builder.json`](../electron-builder.json) | See the table below |
| Linux sandbox | `linux.executableArgs: []` in [`electron-builder.json`](../electron-builder.json) | electron-builder's default desktop entry passed `--no-sandbox`. It no longer does. The AppImage launcher (AppRun) still adds `--no-sandbox` when `unshare -Ur true` fails, that is on hosts without user namespaces |

Both new modules import nothing from Electron, so Vitest can test them.

### Fuses

| Fuse | Value | Effect |
|------|-------|--------|
| `runAsNode` | false | `ELECTRON_RUN_AS_NODE` is ignored |
| `enableCookieEncryption` | true | Cookies are encrypted on disk |
| `enableNodeOptionsEnvironmentVariable` | false | `NODE_OPTIONS` is ignored |
| `enableNodeCliInspectArguments` | false | `--inspect` and similar are ignored |
| `enableEmbeddedAsarIntegrityValidation` | true | `app.asar` is checked on Windows and macOS. Electron has no such check on Linux |
| `onlyLoadAppFromAsar` | true | The app is loaded only from `app.asar` |
| `grantFileProtocolExtraPrivileges` | false | `file://` gets no extra rights |
| `resetAdHocDarwinSignature` | true | Re-signs an unsigned macOS build after the fuses change the binary |

A packaged app can no longer be debugged with `--inspect` or the developer tools. Use `npm run electron:dev`, which keeps them.

## Content-Security-Policy (#104)

`csp` in [`vite.config.js`](../vite.config.js) is passed to SvelteKit (`kit.csp`, hash mode) unless `BUILD_TARGET=capacitor`. SvelteKit writes it as a `<meta>` tag with the hashes of its own inline scripts. The directives are listed in [Architecture](architecture.md#content-security-policy).

| Build | CSP |
|-------|-----|
| Web (`npm run build`) | Yes |
| Electron (loads the web build) | Yes |
| Mobile (`npm run build:mobile`) | No |

The inline dark mode script in [`src/app.html`](../src/app.html) would be blocked. It is now the file [`static/theme-init.js`](../static/theme-init.js), loaded after `%sveltekit.head%` so the CSP `<meta>` comes first and covers it. Its `localStorage` read is now inside `try/catch`; when storage is blocked it follows the system setting.

## Checks

**Automated:** `npm run test:run` 3867 passed, 1 todo, 33 files. `npm run build` and `npm run build:mobile` pass. `npm run audit:check` passes.

The new tests cover the menu template (packaged and not, macOS and not), the three permission handlers, the fuses and `executableArgs` in `electron-builder.json`, the exact `js-ballistics` version and `adapter-static` out of `dependencies`.

**Electron runtime**, Linux only, under Xvfb, Electron 45.2.3. Run from scripts that are not kept.

| Check | Result |
|-------|--------|
| Start: unpacked dir, extracted AppRun, `.AppImage` (`APPIMAGE_EXTRACT_AND_RUN=1`) | All open `app://-/` with the CSP `<meta>` |
| Pages: ballistic, trajectory-validation (ApexCharts drawn), scope-view, profiles/new, fr/settings/about, dope-cards | No CSP violation |
| `Notification.requestPermission()` | `denied` |
| `permissions.query` for geolocation, notifications, camera, microphone, clipboard-read | All `denied` |
| Geolocation request | Error code 1 (permission denied) |
| Control: `develop`'s `main.js` repacked in the same fused binary | All granted, so the checks can fail |
| `--no-sandbox` on any process command line | None (the host has user namespaces) |
| `@electron/fuses read` | Fuse states as configured. One fuse shows as "undefined is Enabled": a newer fuse that reader 1.8 does not name |
| `ELECTRON_RUN_AS_NODE=1` with a script | The script did not run; the app started instead |

Playwright's `waitForFunction`, which uses `eval`, was blocked by the CSP in Electron. This confirms the policy has no `unsafe-eval`.

**Web build** in headless Chromium, from a static server with the SPA fallback:

- 13 routes, including `/fr` and `/de`: no CSP violation, no console error.
- Dark and light theme from `localStorage` work.
- Imperial and metric dope card PDFs downloaded (26504 and 26701 bytes), and the trajectory CSV.
- Control: an injected inline script and a remote image were blocked.

**Mobile build**, served the same way: no CSP `<meta>`, routes and theme work, no errors.

## Security review

**PASS**, no Critical, High or Medium findings.

Applied from its low notes:

- `theme-init.js` loads after the CSP `<meta>`, not before it.
- `resetAdHocDarwinSignature` added.

Remaining notes, not changed:

- `app.asar` integrity is not checked on Linux. Electron has no such check there.
- A `<meta>` CSP cannot set `frame-ancestors`, so other sites can frame the web build. This is not new. It needs a header from the web host, for example in `static/.htaccess`.
- A packaged app still accepts Chromium's `--remote-debugging-port`. There is no fuse for it, and whoever passes it already controls the machine.
